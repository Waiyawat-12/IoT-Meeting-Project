อินเทอร์เน็ตไม่ใช่เครือข่ายเดียว แต่คือเครือข่ายที่เชื่อมกันด้วยโพรโทคอล เครือข่ายภูมิภาค องค์กร และมือถือ มาบรรจบที่โครงข่ายหลัก (Global ISP)

แพ็กเก็ตเดินผ่านที่ไหน

  • PAN: master + slave (หูฟัง นาฬิกา รถ) Bluetooth แย่งคลื่นระยะสั้น
  • บ้าน: เกตเวย์ออก ISP, โมเด็ม DSL/เคเบิล, ทั้งทราฟฟิกยืดหยุ่น (เว็บ) และสตรีมที่อ่อนไหวต่อเวลา, เซ็นเซอร์ IoT
  • NAT: โฮสต์ภายในหลายเครื่อง (10.0.0.1–3) ใช้ IP สาธารณะตัวเดียว (เช่น 138.76.29.7) IP ภายในมีความหมายแค่ในบ้าน
  • LAN องค์กร: เราเตอร์สถาบัน, สวิตช์ core/edge, 1–10 Gbps, แชร์เซิร์ฟเวอร์ สวิตช์แยก collision domain
  • VLAN (เกริ่น): สายเดิม แต่จัดกลุ่มตามแผนกหรือความปลอดภัย ไม่ตามห้อง

รูปของเครือข่ายไร้สาย

  • Wi-Fi infrastructure: สถานีผ่าน AP เข้าสาย Ad hoc: สถานีคุยกันตรง ไม่มี AP แชร์ช่องสัญญาณเดียวกัน
  • เซลลูลาร์: UE ↔ สถานีฐาน (eNodeB) ↔ core การโอนย้าย: (1) เกาะเสาปัจจุบัน (2) วัดเสาข้างเคียงและเตรียม (3) ส่งมอบเซสชันโดยสตรีมไม่ขาด
  • ศูนย์ข้อมูล: core router, edge switch, แร็ค Load balancing กระจายงาน ใช้กับคลาวด์ (Netflix, Google)

โฮสต์และมาตรฐาน

โฮสต์ / end system คืออุปกรณ์ที่รันแอปบนเครือข่าย: PC, โทรศัพท์, แร็คเซิร์ฟเวอร์, เซ็นเซอร์ IoT โพรโทคอล คือข้อตกลงเรื่องรูปแบบ ลำดับ และการกระทำของข้อความ มาตรฐาน (HTTP, TCP, …) ทำให้ผู้ผลิตต่างค่ายคุยกันได้ แพ็กเก็ตมีเพย์โหลด เส้นทางเพิ่มความหน่วง และภัยคุกคามอยู่บนเส้นทางเดียวกัน

เพิ่มเติม ลิงก์เฉพาะ (FTTH, DSL, Ethernet แบบสวิตช์) ไม่แชร์ฮอปล่าสุด HFC กับ Wi-Fi แชร์ เพื่อนบ้านจึงทำให้ช้าได้ แม้ตัวเลขบนโมเด็มจะสูง

ความหน่วง 4 ชนิด

d_end-end = d_proc + d_queue + d_trans + d_prop
d_proc: ตรวจเฮดเดอร์ แล้วตัดสินใจส่งต่อ
d_queue: รอในบัฟเฟอร์
d_trans = L / R   (เวลาผลักบิตลงสาย)
d_prop = d / s   (สัญญาณเดินทาง; ไฟเบอร์ s ≈ 2×10^8 m/s)

Transmission คือด่านเก็บเงิน (นานแค่ไหนกว่าจะปล่อยรถลงถนน) Propagation คือการขับ (ระยะ/ความเร็ว) คนละตัวแปรกัน

โจทย์จากสไลด์

  • L = 4,000 บิต, R = 2 Mbps → d_trans = 4000/2×10^6 = 2 ms
  • รูป 5 MB, อัปสตรีม HFC 10 Mbps ใช้ 1 MB = 10^6 ไบต์ → L = 4×10^7 บิต d_trans = 4×10^7/10^7 = 4 วินาที
  • 1,000 ไบต์, 2,000 กม., 10 Mbps, s = 2×10^8 m/s
    d_trans = 8,000/10^7 = 0.8 ms
    d_prop = 2×10^6 / 2×10^8 = 10 ms การเดินทางนานกว่าการผลักบิต

ทรูพุตและการสูญหาย

Throughput = min(R1, R2, R3, …)
ตัวอย่าง: 2 Mbps | 100 kbps | 1 Mbps → 100 kbps
ความเข้มทราฟฟิก I = L a / R
a = อัตราแพ็กเก็ตเข้าเฉลี่ย ถ้า I > 1 คิวโตไม่หยุด บัฟเฟอร์เต็ม แพ็กเก็ตใหม่ถูกทิ้ง ความหน่วงพุ่งเมื่อ I เข้าใกล้ 1
เพิ่มเติม กับดักหน่วย: Mb ≠ MB (คูณ 8) สไลด์ใช้ 10^6 ไม่ใช่ 2^20 เว้นแต่โจทย์บอกไว้ d_trans ไม่ขึ้นกับระยะ d_prop ไม่ขึ้นกับ L และ R ความหน่วงต่อโหนดคือสี่พจน์นี้ ปลายทางถึงปลายทางคือผลรวมตลอดเส้นทาง และคิวคือพจน์ที่เปลี่ยนตามโหลด

การห่อหุ้ม (encapsulation)

แต่ละชั้นเติมเฮดเดอร์ สวิตช์ดูเฮดเดอร์ลิงก์อย่างเดียว แล้วส่งเฟรมต่อ เราเตอร์ถอดเฟรม อ่านเฮดเดอร์ IP แล้วสร้างเฟรมใหม่สำหรับลิงก์ถัดไป IP ต้นทางและปลายทางไม่เปลี่ยนข้ามฮอป MAC กับ FCS เปลี่ยนทุกฮอป เปรียบเทียบ: ตั๋ว (L3) บอกเมืองปลายทาง พาหนะ (L2) เป็นของท้องถิ่น

ทำไมต้องหั่นข้อความ

ส่ง 10^6 บิต ผ่าน 3 ลิงก์ ที่ 5 Mbps ทั้งก้อนใช้ 0.2 วินาทีต่อลิงก์ Store-and-forward ทั้งก้อน: 3 × 0.2 = 0.6 วินาที

หั่นเป็น 100 แพ็กเก็ต ใบละ 10^4 บิต (ใบละ 0.002 วินาที) เวลาแบบไปป์ไลน์ = (3 + 100 − 1) × 0.002 = 0.204 วินาที

ภัยบนเส้นทาง

  • มัลแวร์ที่แพร่เอง (เวิร์ม): กระจายโฮสต์สู่โฮสต์ โดยผู้ใช้ไม่ต้องเปิดไฟล์
  • บอตเน็ต / DDoS: โฮสต์ที่ถูกยึดจำนวนมากยิงขยะใส่เป้าเดียวกันพร้อมกัน
  • MITM: Trudy นั่งระหว่าง Alice กับ Bob อ่านหรือแก้แพ็กเก็ตได้
เพิ่มเติม Packet switching มีไว้เพื่อไม่ให้การส่งก้อนใหญ่แช่แข็งเราเตอร์ทุกตัวจนกว่าวัตถุทั้งก้อนจะข้าม ราคาที่จ่ายคือเฮดเดอร์ การประกอบกลับ และการที่แพ็กเก็ตแต่ละใบอาจหาย Wireshark บนพีซีปกติไม่แสดง preamble, SFD และ FCS แม้บนสายจะมี

แอปถูกสร้างอย่างไร

  • Client–server: ไคลเอนต์ขอ เซิร์ฟเวอร์ที่เปิดตลอดตอบ (เว็บ เมล ส่วนควบคุมของสตรีม)
  • P2P: ไม่มีศูนย์ที่เปิดตลอด แต่ละเพียร์เป็นทั้งไคลเอนต์และเซิร์ฟเวอร์ (BitTorrent) เพียร์ยิ่งมาก ความจุยิ่งเพิ่มได้
  • แอปที่ควรเรียกชื่อได้: เว็บ เมล วิดีโอสตรีม VoIP เกม ค้นหา ล็อกอินระยะไกล แชต

โปรเซสและซ็อกเก็ต

โปรเซส คือโปรแกรมที่กำลังรัน โฮสต์เดียวกันคุยผ่าน OS คนละโฮสต์ส่งข้อความผ่านซ็อกเก็ต (ประตู) จะรับข้อความได้ โปรเซสต้องมีตัวระบุ: ที่อยู่ IP + หมายเลขพอร์ต IP หาเครื่อง พอร์ตหาโปรเซส

เว็บและ HTTP

หน้าเว็บคือวัตถุ (HTML, JPEG, …) แต่ละชิ้นมี URL อาจอยู่คนละเซิร์ฟเวอร์ HTTP คือโพรโทคอลชั้นแอป: ไคลเอนต์/เซิร์ฟเวอร์ พอร์ต 80 ปกติ ใช้ TCP ตัว HTTP ไร้สถานะ (เซิร์ฟเวอร์ไม่จำคำขอเก่า เว้นแต่คุกกี้มาช่วย)

การเชื่อมต่อ

  • Non-persistent: หนึ่งการเชื่อมต่อ TCP ส่งได้อย่างมากหนึ่งวัตถุ เปิด ส่ง ปิด ราคา ≈ 2 RTT + เวลาส่งไฟล์ ต่อวัตถุ (แฮนด์เชค + ขอ/ตอบ) และมีโอเวอร์เฮดของ OS ทุกครั้ง
  • Persistent (HTTP/1.1): ตั้ง TCP ครั้งเดียว (1 RTT) แล้วส่งหลายวัตถุบนสายนั้น วัตถุละประมาณ 1 RTT บวกเวลาส่ง เซิร์ฟเวอร์อาจเปิดสายค้างไว้
RTT = แพ็กเก็ตเล็กไปเซิร์ฟเวอร์แล้วกลับ หน้าแบบ non-persistent ที่มี HTML 1 ไฟล์ + รูป 10 รูป ≈ 11 × (2 RTT + เวลาส่ง) ถ้าเปิดทีละสาย

  • ไปป์ไลน์ HTTP/1.1: ส่ง GET หลายอันบน TCP เดียว แต่เซิร์ฟเวอร์ตอบตามลำดับ วัตถุใหญ่ขวางวัตถุเล็ก (HOL blocking) เซกเมนต์ TCP ที่หายจะหยุดทุกวัตถุบนสายนั้น
  • HTTP/2: เมธอดและรหัสเดิม หั่นวัตถุเป็นเฟรมแล้วสลับส่ง (multiplexing) วัตถุเล็กไม่ต้องรอวัตถุใหญ่ แต่ยังเป็น TCP เดียว แพ็กเก็ตหายยังหยุดทั้งสาย
  • HTTP/3 = QUIC บน UDP: การเชื่อมต่อ กู้แพ็กเก็ตหาย และควบคุมความแออัด อยู่ในยูเซอร์สเปซ สตรีมอิสระ แพ็กเก็ตหายสายหนึ่งไม่แช่แข็งสายอื่น แฮนด์เชครวมทรานสปอร์ตกับ TLS ได้ 0-RTT ใช้ตั๋วเซสชัน TLS ส่งข้อมูลได้ตั้งแต่เที่ยวแรก

พาริตี

พาริตีคู่: เติมบิตให้จำนวน 1 เป็นคู่ พาริตีคี่: ให้เป็นคี่ วงจรสร้างและตรวจคือ XOR ตัวเดียวกัน ตัวอย่างคำว่า world ใน ASCII 7 บิต บวกพาริตีคู่ ส่งเป็นหน่วย 8 บิต บิตพลิกแล้วซินโดรมเป็น 1

พาริตีธรรมดาจับผิดบิตเดียวได้ทุกกรณี และจับเบิร์สต์ได้ก็ต่อเมื่อจำนวนบิตเสียในหน่วยนั้นเป็นเลขคี่ พลิกสองบิตในหน่วยเดียวกันจะมองไม่เห็น

พาริตีสองมิติ: พาริตีทุกแถวและทุกคอลัมน์ บิตเสียหนึ่งตำแหน่งจะทำให้แถวหนึ่งและคอลัมน์หนึ่งไม่ผ่าน จึงแก้ตำแหน่งนั้นได้ ส่งทีละแถว พร้อมบิตพาริตี

เช็กซัม (one’s complement)

หั่นข้อความเป็นหน่วย m บิต บวกแบบมีตัวทดวนปลาย แล้วส่งส่วนเติมเต็ม ผู้รับบวกข้อความ + เช็กซัม ถ้าส่วนเติมเต็มของผลบวกเป็น 0 แสดงว่าสะอาด เช็กซัมเฮดเดอร์ IPv4 คลุมเฉพาะเฮดเดอร์ เช็กซัม TCP/UDP คลุมเฮดเดอร์ + ข้อมูล ลิงก์ชอบ CRC มากกว่าเพราะจับเบิร์สต์ได้ดี

ส่ง: 10101001 00111001 00011101 ผลบวกสามส่วน = 11111111 → ส่วนเติมเต็ม 00000000 (ผ่าน)

CRC

มองข้อมูลเป็นพหุนาม ตกลงตัวหารกัน เติมศูนย์ท้าย r ตัว (เท่าดีกรี) แล้วหารแบบโมดูโล-2 (XOR ไม่ยืม) เศษคือ CRC สั้นกว่าตัวหารหนึ่งบิต โค้ดเวิร์ด = ข้อมูล + เศษ หารตัวหารลงตัว ผู้ตรวจหารอีกครั้ง เศษไม่เป็นศูนย์แปลว่าผิด

CRC(7,4) ในสไลด์ ตัวหาร 1011 เศษ 110 โค้ดเวิร์ดลงท้ายด้วย 3 บิตนี้ การลบแบบโมดูโล-2 คือ XOR

Hamming (พาริตีคู่)

บิตพาริตีอยู่ที่กำลังของ 2: r1, r2, r4, r8, … แต่ละตัวตรวจตำแหน่งที่ดัชนีมีบิตนั้นติด ข้อมูล 1001101 วางเป็น d7…d1 คั่นบิตพาริตี ได้โค้ดเวิร์ด 10011100101

ตำแหน่ง 11→1: d7 d6 d5 r8 d4 d3 d2 r4 d1 r2 r1
= 1 0 0 1 1 1 0 0 1 0 1
รับมา 10010100101 ตรวจ: r1=1, r2=1, r4=1, r8=0 ซินโดรม r8 r4 r2 r1 = 0111 = 7 พลิกบิตที่ 7

Interleaving: สลับบิตของหลายโค้ดเวิร์ด เบิร์สต์จะโดนโค้ดเวิร์ดละหนึ่งบิต แล้ว Hamming แก้ทีละคำได้

เพิ่มเติม พาริตีพลาดเมื่อจำนวนบิตพลิกเป็นเลขคู่ เช็กซัมพลาดเบิร์สต์ได้หลายแบบ CRC (FCS) คือสิ่งที่ Ethernet, Wi-Fi, HDLC และ PPP ใช้จริงบนลิงก์ การแก้ผิด (Hamming, interleaving) ใช้เมื่อส่งใหม่แพงหรือทำไม่ได้

การควบคุมการไหล

ผู้ส่งต้องไม่เร็วกว่าผู้รับ ทั้งสองฝั่งมีบัฟเฟอร์ ถ้าบัฟเฟอร์ผู้รับเต็ม เฟรมหายได้แม้สายจะดี

  • โพรโทคอลธรรมดา: ไม่ควบคุมการไหล ไม่ควบคุมข้อผิดพลาด ไม่มีเลขลำดับ ส่งเมื่อมีข้อมูล
  • Stop-and-wait ARQ: ส่งหนึ่งเฟรม รอ ACK (ผู้รับตรวจ CRC) เลขลำดับมีแค่ 0 กับ 1 เพื่อไม่ให้เฟรมที่ส่งซ้ำถูกนับเป็นเฟรมใหม่

กรณีของ stop-and-wait: ACK ปกติ, เฟรมหาย → ไทม์เมอร์ ส่งเลขเดิมซ้ำ, ACK หาย → ผู้ส่งส่งซ้ำ ผู้รับเห็นเลขซ้ำจึงทิ้งแต่ ACK ใหม่, ACK มาช้า → เลข 0/1 แยก ACK เก่าออกจาก ACK ของเฟรมถัดไป

การชนคือมีสัญญาณสองทางขึ้นไปบนสื่อร่วมพร้อมกัน (บัสหรือฮับ) ระดับสัญญาณเพี้ยน สวิตช์ฟูลดูเพล็กซ์ไม่มีการชน

ALOHA

ส่งทันทีที่มีเฟรม (ไร้สายยุคแรก 9600 bps) ไม่ฟังสื่อก่อน ชนแล้วสุ่ม backoff แล้วลองใหม่ Pure: ส่งเมื่อไรก็ได้ ช่วงเสี่ยง 2T ทรูพุตสูงสุด ~18% Slotted: ส่งได้แค่ต้นสล็อต ต้องซิงก์ ช่วงเสี่ยง T สูงสุด ~37%

CSMA

ฟังก่อน ถ้าว่างจึงส่งได้ ยังชนได้: สองสถานีได้ยินว่าว่าง แล้วสัญญาณมาชนกันหลังความหน่วงการเดินทาง

  • Non-persistent: ถ้าไม่ว่าง รอสุ่ม แล้วฟังใหม่ ชนน้อยลง แต่มีช่องว่างมากขึ้น
  • 1-persistent: ถ้าไม่ว่าง ให้ฟังต่อ ส่งทันทีที่ว่าง โลภ สถานีชนกันตอนเฟรมยาวจบ Ethernet รุ่นคลาสสิก
  • p-persistent: ถ้าว่าง ส่งด้วยความน่าจะเป็น p ไม่งั้นรอหนึ่งสล็อต p = 0.2 คือโอกาสส่งในสล็อตนี้ 20%

CSMA/CD (Ethernet สายที่ใช้ร่วม)

ฟัง ส่ง และฟังต่อระหว่างส่ง ชนแล้วหยุด ส่ง jam แล้วลองใหม่ หลังชนครั้งที่ n ให้ k = min(n, 10) สุ่ม r จาก 0 … 2^k−1 รอ r × สล็อต สล็อต ≥ 2 T_prop,max สล็อต Ethernet 10 Mbps = 512 บิต-ไทม์ = 51.2 µs ยอมแพ้หลังชนมากเกินไป (16 ครั้ง)

CSMA/CA (802.11)

ผู้ส่งไร้สายไม่ได้ยินการชนขณะตัวเองส่ง และสถานีที่ซ่อนอยู่อาจไม่ได้ยินอีกฝ่าย จึงเลี่ยงการชน ไม่ใช่ตรวจการชน

  • รอ DIFS (หรือ SIFS ที่สั้นกว่า สำหรับ ACK, CTS และเฟรมสำคัญ) แล้ว backoff สุ่มที่นับเฉพาะตอนช่องว่าง
  • CW backoff สุ่มว่าจะรอกี่สล็อต (CW = 15 จับได้ 7 → รอ 7) คนละแบบกับ p-persistent ที่ทอยเหรียญทุกสล็อต
  • ผู้รับ ACK หลัง SIFS ไม่มี ACK → ถือว่าหาย ขยาย CW แล้วลองใหม่
  • NAV: เฟรมใส่ Duration สถานีอื่นชะลอแม้จะไม่ได้ยินข้อมูล (virtual carrier sense)
  • RTS/CTS (ทางเลือก, DCF): จองสื่อ เพื่อให้สถานีที่ซ่อนอยู่ได้ยิน CTS แล้วตั้ง NAV
  • EDCA: เสียง/วิดีโอรอสั้นกว่าทราฟฟิกทั่วไป

Wi-Fi 4 (802.11n): MIMO, รวมช่อง Wi-Fi 5 (ac): DL MU-MIMO, ช่องกว้างขึ้น Wi-Fi 6 (ax): OFDMA + UL/DL MU-MIMO Wi-Fi เป็นเครื่องหมายการค้า IEEE 802.11 คือมาตรฐาน

ผลัดกัน และแบ่งช่อง

  • จองคิว: มินิสล็อตจองหนึ่งช่องต่อสถานี แล้วตามด้วยข้อมูลของคนที่จอง
  • โพลล์: มีฝ่ายหลัก (master) กับฝ่ายรอง Select: ฝ่ายหลักเตือน รอยืนยันพร้อม แล้วส่ง Poll: ฝ่ายหลักถามทีละฝ่ายรอง NAK แปลว่าไม่มีอะไรจะส่ง
  • โทเคน: สถานีเรียงเป็นวงตรรกะ คนถือโทเคนเท่านั้นที่ส่ง แล้วส่งโทเคนต่อ สายจริงไม่จำเป็นต้องเป็นวง

FDMA: แต่ละสถานีได้ย่านความถี่ (FDM ข้างล่าง) เซลลูลาร์ ดาวเทียม TDMA: ทั้งย่าน แต่ผลัดกันตามเวลา (TDM ข้างล่าง) CDMA: ทุกสถานี ส่งพร้อมกัน ทั้งย่าน แยกกันด้วยรหัส

รหัส Walsh ของ CDMA ตั้งฉากกัน กฎ: ข้อมูล 0 → ส่ง −1 คูณรหัส ข้อมูล 1 → ส่ง +1 คูณรหัส ไม่ว่าง → 0 ผลบวกบนช่องเป็นเวกเตอร์เดียว สถานี i กู้บิตด้วยผลคูณภายในกับรหัสของตน: ผล / N เป็น +1, −1 หรือ 0 ผลคูณภายในของรหัสกับตัวเองคือ N กับรหัสอื่น (หรือส่วนเติมเต็ม) คือ 0

ที่อยู่ MAC

48 บิตบน NIC เขียนเป็นเลขฐานสิบหกคั่นโคลอน (4A:30:10:21:10:1A) 24 บิตแรกคือ OUI (IEEE, ผู้ผลิต) 24 บิตหลังคือซีเรียลของผู้ผลิต ที่อยู่ซ้ำเกิดได้ (โรงงานพลาด หรือ VM) เมื่อนั้นเปลี่ยน NIC หรือแก้ในซอฟต์แวร์

  • ส่งทีละไบต์จากซ้ายไปขวา แต่ในแต่ละไบต์ส่ง LSB ก่อน บิตที่บอกยูนิคาสต์/มัลติคาสต์จึงไปถึงก่อน
  • ยูนิคาสต์: I/G = 0 NIC ใบเดียว มัลติคาสต์: I/G = 1 (เช่น IGMP) บรอดคาสต์: FF:FF:FF:FF:FF:FF DHCP กับ ARP ต้องใช้บรอดคาสต์
  • บนสายที่ใช้ร่วม ทุก NIC ได้ยินทุกเฟรม แล้วเก็บเฉพาะของตน บรอดคาสต์ หรือมัลติคาสต์ที่ตนเข้ากลุ่ม

ซับเน็ตเดียวกัน: MAC ของเฟรม = โฮสต์ปลายทาง คนละเครือข่าย: MAC ของเฟรม = เกตเวย์ (เราเตอร์ปริยาย) IP ในแพ็กเก็ตไม่เปลี่ยน เราเตอร์สร้างเฟรมใหม่

ความเร็วและสวิตช์

  • Ethernet ใช้ร่วมแบบมาตรฐาน: CSMA/CD แบบ 1-persistent สายยาวได้ประมาณ 2500 ม.
  • Fast (100 Mbps): เฟรมสั้นสุดยัง 64 B แต่เร็วขึ้น 10 เท่า สายที่ใช้ร่วมจึงเหลือ 250 ม. (ในทางปฏิบัติ UTP 100 ม.) Fast Ethernet แบบสวิตช์เป็นฟูลดูเพล็กซ์ ไม่ใช้ CSMA/CD Autonegotiation เลือกความเร็วร่วม มักเป็นฝั่งที่ช้ากว่า
  • Gigabit 802.3z: รูปแบบเฟรมเดิม มี autonegotiation กรณีฮาล์ฟดูเพล็กซ์เก่า ความยาวขั้นต่ำกลายเป็น 512 B (carrier extension) เฟรมสั้นอาจถูกมัดรวม (frame bursting) ไม่มีฮับระดับ Gbps สวิตช์ฟูลดูเพล็กซ์ไม่มีการชน จึงไม่ใช้ส่วนขยายนั้น

การส่งต่อ

  • ต้นทางที่ไม่รู้จัก → เรียนรู้ MAC + พอร์ต ปลายทางที่รู้จัก → ส่งเฉพาะพอร์ตนั้น ปลายทางไม่รู้จัก บรอดคาสต์ หรือมัลติคาสต์ → flood
  • พอร์ตที่ต่อไปอีกสวิตช์ถือ MAC ได้หลายตัว
  • Store-and-forward: รับทั้งเฟรม ตรวจ CRC แล้วส่งต่อ จำเป็นถ้าจะทำ QoS จากชนิดเฟรม
  • Cut-through: ส่งต่อเมื่อเห็น DA แล้ว เร็ว ไม่ทำ QoS อาจส่งเฟรมที่ CRC เสีย Fragment-free รอ 64 B (หน้าต่างการชนยุคเก่า) แล้วตัดผ่าน
  • Auto-MDIX รับได้ทั้งสายตรงและสายไขว้ ไม่ใช่ autonegotiation (ความเร็ว/ดูเพล็กซ์)

ARP

บน LAN ท้องถิ่น เฟรมต้องมี MAC ARP แปลง IPv4 → MAC A บรอดคาสต์คำขอ (ช่อง MAC เป้าหมายเป็นศูนย์ทั้งหมด) เจ้าของยูนิคาสต์ตอบกลับ ทั้งสองฝั่งแคชไว้ (arp -a) ARP ไม่ข้ามเราเตอร์ เมื่อ IP อยู่ไกล โฮสต์จะ ARP หาเกตเวย์

VLAN

ไม่มี VLAN สวิตช์ที่ต่อกันคือ broadcast domain ชั้น 2 ก้อนใหญ่ VLAN คือกลุ่มเชิงตรรกะ แต่ละ VLAN เป็น broadcast domain ของตัวเอง: น้ำท่วมเล็กลง แยกกลุ่มได้ (ความปลอดภัย แผนก) และย้ายพอร์ตได้โดยไม่ย้ายสาย

  • VLAN ปริยาย: VLAN 1 พอร์ต access ที่ยังไม่กำหนดตกมาที่นี่ อย่าใช้กับผู้ใช้
  • VLAN ข้อมูล กับ VLAN เสียง พอร์ต access มี VLAN ข้อมูลได้หนึ่ง และอาจมี VLAN เสียงได้อีกหนึ่ง โทรศัพท์ VoIP คือสวิตช์ 3 พอร์ตตัวเล็ก CDP บอกโทรศัพท์ว่าต้องแท็ก VLAN เสียงไหน
  • Native VLAN (เฉพาะทรังก์): เฟรมของ VLAN นี้ไปแบบไม่ติดแท็ก VLAN อื่นบนทรังก์ 802.1Q ติดแท็กทั้งหมด
  • แท็ก 802.1Q ยาว 4 ไบต์ แทรกหลัง MAC ต้นทาง: TPID 0x8100 + TCI (priority, DEI, รหัส VLAN 12 บิต) คำนวณ FCS ใหม่
  • พอร์ต access: VLAN ข้อมูลเดียว ไปหาโฮสต์ปลาย ไม่ติดแท็กบนสาย ทรังก์: จุดต่อจุดระหว่างสวิตช์ (หรือสวิตช์กับเราเตอร์) แบกหลาย VLAN
  • ช่วงบน Catalyst 2960/3650: ปกติ 1–1005 (เก็บใน vlan.dat สร้างในโหมด global) แบบขยาย 1006–4094 มีรหัส VLAN ได้กว่า 4000 แต่สวิตช์ยังมีเพดานจำนวนที่ใช้งานพร้อมกันน้อยกว่านั้น
