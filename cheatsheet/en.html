The Internet is not one network. It is networks joined by protocols: regional, enterprise, and mobile networks meet a core (Global ISP).

Places a packet lives

  • PAN: master + slaves (earbuds, watch, car). Bluetooth fights overlap on a short radio.
  • Home: gateway to the ISP; DSL/cable modem; mix of elastic web and time-sensitive streams; IoT sensors.
  • NAT: many private hosts (10.0.0.1–3) share one public address (e.g. 138.76.29.7). Inside addresses mean something only in the house.
  • Enterprise LAN: institutional router, core/edge switches, 1–10 Gbps, shared servers. Switches separate collision domains.
  • VLAN preview: same cables, new groups by department or security, not by room.

Wireless shapes

  • Wi-Fi infrastructure: stations via an AP onto a wired net. Ad hoc: stations talk directly, no AP. One radio channel is shared.
  • Cellular: UE ↔ base station (eNodeB) ↔ core. Handover: (1) associate with the current tower, (2) measure the neighbor and prepare, (3) move the session so the flow does not stall.
  • Data center: core routers, edge switches, racks. Load balancing spreads work. Purpose: cloud apps (Netflix, Google).

Who runs the core

  • Access ISP → regional ISP → tier-1 ISP. Tier-1s peer with each other.
  • Peering (often at an IXP) avoids paying a transit fee to a lower-tier ISP.
  • Content networks (Google and others) build their own paths and caches so traffic does not all buy transit, and so data sits near users.

Hosts and standards

A host / end system is anything that runs a networked app: PC, phone, rack server, IoT sensor. A protocol is the agreed message format, order, and actions. Standards (HTTP, TCP, …) let different vendors interoperate. A packet carries payload, and the path adds delay; security threats sit on the same path.

EXTRA Dedicated access (FTTH, DSL, switched Ethernet) does not share the last hop. HFC and Wi-Fi do, so a neighbor’s traffic can slow you even when your modem rate looks high.

Four delays

dend-end = dproc + dqueue + dtrans + dprop
dproc: check header, decide where next
dqueue: wait in the buffer
dtrans = L / R   (push the bits onto the wire)
dprop = d / s   (signal travel; fiber s ≈ 2×108 m/s)

Transmission is the toll booth (how long to put cars on the road). Propagation is the drive (distance / speed). They do not depend on the same variables.

Worked (slides)

  • L = 4,000 bit, R = 2 Mbps → dtrans = 4000/2×106 = 2 ms.
  • 5 MB image, HFC upstream 10 Mbps. Use 1 MB = 106 bytes → L = 4×107 bit. dtrans = 4×107/107 = 4 s.
  • 1,000 bytes, 2,000 km, 10 Mbps, s = 2×108 m/s.
    dtrans = 8,000/107 = 0.8 ms.
    dprop = 2×106 / 2×108 = 10 ms. Propagation dominates.

Throughput and loss

Throughput = min(R1, R2, R3, …)
Example: 2 Mbps | 100 kbps | 1 Mbps → 100 kbps.
Traffic intensity I = L a / R
a = average packet arrival rate. If I > 1, the queue grows without bound, the buffer fills, new packets are dropped. Delay shoots up as I → 1.
EXTRA Unit traps: Mb ≠ MB (×8). Slides use 106, not 220, unless they say otherwise. dtrans ignores distance. dprop ignores L and R. Nodal delay on one link is those four terms; end-to-end sums them over the path, and queueing is the one that varies with load.

Encapsulation

Each layer adds a header. A switch looks at the link header only and forwards the frame. A router strips the frame, reads the IP header, and builds a new frame for the next link. IP source and destination stay the same across hops. MAC addresses and the FCS change every hop. Analogy: the ticket (L3) names the destination city; each vehicle (L2) is local.

Why cut the message up

Send 106 bits over 3 links at 5 Mbps. One packet per link takes 0.2 s. Store-and-forward of the whole block: 3 × 0.2 = 0.6 s.

Split into 100 packets of 104 bits (0.002 s each). Pipelined time = (3 + 100 − 1) × 0.002 = 0.204 s.

Security on the path

  • Self-replicating malware (worms): spreads host to host without a user opening a file.
  • Botnet / DDoS: many compromised hosts send junk at one target at the same time.
  • MITM: Trudy sits between Alice and Bob and can read or change the packets.
EXTRA Packet switching exists so one huge transfer does not freeze every router until the whole object has crossed. The price is headers, reassembly, and possible loss of individual packets. Wireshark on a PC usually hides the Ethernet preamble, SFD, and FCS even though they are on the wire.

How apps are built

  • Client–server: client requests, always-on server answers (Web, mail, streaming control).
  • P2P: no always-on center; each peer is client and server (BitTorrent). More peers can mean more capacity.
  • Apps you should name: Web, mail, streaming video, VoIP, games, search, remote login, messaging.

Processes and sockets

A process is a running program. Same host: OS communication. Different hosts: messages through a socket (the door). To receive, a process needs an identifier: IP address + port number. IP finds the host; the port finds the process.

Web and HTTP

A page is objects (HTML, JPEG, …), each with a URL, possibly on different servers. HTTP is the app protocol: client/server, usually port 80. It uses TCP. HTTP itself is stateless (the server keeps no memory of past requests unless cookies add it).

Connections

  • Non-persistent: at most one object per TCP connection. Open, send, close. Cost ≈ 2 RTT + file transmission per object (handshake + request/response). OS overhead per connection.
  • Persistent (HTTP/1.1): one TCP setup (1 RTT), then many objects on that connection, about 1 RTT per object, plus transmission. Server may leave the connection open.
RTT = small packet to the server and back. Non-persistent page with 1 HTML + 10 images ≈ 11 × (2 RTT + trans) if opened one after another.

Messages

Request: method, URL, version, then headers, blank line, optional body.
Response: version, status code, phrase, headers, blank line, body.

MethodIdea
GETFetch object. Query in URL.
POSTSend form / body to the server.
HEADHeaders only, no body.
PUT / DELETEUpload / remove an object.

Status: 200 OK, 301 Moved, 304 Not Modified, 400 Bad Request, 404 Not Found, 505 HTTP version not supported. Classes: 2xx success, 3xx redirect, 4xx client, 5xx server.

Cookies

HTTP is stateless. Cookies add memory in four parts: (1) Set-Cookie in the response, (2) browser stores the id, (3) later requests send Cookie, (4) server looks the id up in its database.

  • Uses: login session, cart, preferences, tracking / ads.
  • First-party: the site you are on. Third-party: another domain (ad network) tracks you across sites. Example: NYTimes page loads AdX; cookie 1634 records “sports”, later “arts”.
  • Firefox blocks third-party cookies by default (ETP). GDPR: cookie ids and IP addresses can identify a natural person.

Caches

  • Browser cache: on the user’s disk/RAM.
  • Proxy / Web cache: a shared server. It is a server to the client and a client to the origin. Cuts access-link load and delay.

Slide sketch: access link almost full (utilization ≈ 0.97) makes end-to-end delay large (LAN delay is tiny). A cache that satisfies a fraction of requests lowers access utilization and average delay.

Conditional GET

Client sends If-Modified-Since: <date>. Unchanged → 304 Not Modified, no body. Changed → 200 OK and the new object.

HTTP/1.1 → HTTP/2 → HTTP/3

  • HTTP/1.1 pipelining: many GETs on one TCP, but the server answers in order. A large object blocks small ones (HOL blocking). A lost TCP segment stalls every object on that connection.
  • HTTP/2: same methods and codes, objects cut into frames and interleaved (multiplexing) so a small object need not wait. Still one TCP: a loss still stalls the connection.
  • HTTP/3 = QUIC over UDP: connection, loss recovery, and congestion control in user space. Independent streams, so one lost packet does not freeze the others. Handshake can combine transport + TLS. 0-RTT resumption uses a TLS session ticket to send data on the first flight.

Email

  • Three pieces: user agent, mail servers (mailbox + outgoing queue), SMTP.
  • SMTP (RFC 5321): TCP port 25, sending server acts as client, direct to the receiver’s server. Phases: handshake (220, HELO, 250), transfer (354 start mail input), close. Commands are ASCII.
  • Alice’s UA → her server (SMTP or HTTP). Her server → Bob’s server (SMTP). Bob pulls mail with IMAP, POP, or a Web UI.
  • RFC 5322 / 2822 is the message (headers To: From: Subject:, blank line, body). Those headers are not the SMTP envelope (MAIL FROM, RCPT TO).
  • IMAP: mail stays on the server, folders, delete there. POP3: typically download (and often remove). Webmail is HTTP in front of SMTP + IMAP/POP.

DNS

People use names; routers use IP. DNS is a distributed database. Not one central server: single point of failure, traffic, distance, and maintenance.

  • Hierarchy: root → TLD (.com, .org, .th, …) → authoritative (the domain’s own server) → answer. Your host asks a local DNS resolver first.
  • Iterative: each server refers the resolver to the next one (resolver does the walking). Recursive: the asked server chases the name and returns the final answer.
  • Caches store mappings with a TTL. A cached answer can be stale until TTL expires.
RRName → value

DNS message: header (id, flags), questions, answer RRs, authority RRs, additional RRs. Register a name at a registrar, then add NS and A (and MX) records. Attacks: DDoS on root/TLD, spoofed replies, cache poisoning.

Video and CDNs

  • Video = images at a fixed rate (e.g. 24/s). Spatial coding compresses inside a frame; temporal coding sends differences between frames. CBR vs VBR.
  • Stored streaming: record, then send. Constraint: playout must keep original timing, so the client buffers to absorb jitter.
  • DASH: file split into chunks, each chunk encoded at several rates. A manifest lists URLs. The client picks the rate from measured bandwidth.
  • CDN: one mega-server fails distance and overload. Enter deep (servers inside many access nets) or bring home (fewer, larger sites). Netflix: manifest from the service, video from OpenConnect nodes.
EXTRA Socket sketch, not a full program. UDP: no handshake; client sendto / recvfrom with an explicit address each time. TCP: server bind+listen+accept; client connect; both then read/write a byte stream. The app must name the other side’s IP and port; the socket API does not choose them for you.

What the link layer does

Physical layer moves bits. The link layer delivers a frame across one hop. Applications see end-to-end; links are hop-by-hop. At every router the old frame is removed and a new one is built.

  • LLC: talk to the network layer, multiplex protocols. Optional flow and error recovery.
  • MAC: framing, link addresses, FCS, and (on a shared medium) who may transmit.

Dedicated (full-duplex switch port, point-to-point): no fight for the wire. Shared (bus, hub, wireless): two senders can collide. That is the MAC problem (Lecture 6.1, page 4 of this sheet).

Framing

A frame is an envelope: header, payload, trailer (usually FCS), and a way to see the edges. Generic: Flag | Address | Control | Data | FCS | Flag.

TransparencyByte stuffingBit stuffingNo delimiter stuffing
ExamplesBISYNC, SLIP, async PPPHDLC, sync PPP, Frame Relay, CANEthernet, 802.11, ATM
  • Byte stuffing: if the flag byte appears in data, escape it (ESC) so it is not read as a flag. PPP flag is 0x7E. Still seen in PPPoE (DSL/fiber access) and some serial WAN links.
  • Bit stuffing (HDLC): flag = 01111110. Sender inserts a 0 after five 1s in the data; receiver removes that 0. Used on synchronous serial (T1/E1, SONET) and Cisco HDLC.
  • UART uses start/stop bits. I²C uses START/STOP conditions. SPI has no single standard frame. Ethernet padding is not stuffing — it only fills a short frame up to the minimum length.

Errors

Bits flip from interference, thermal noise, bad cable or NIC, lightning, EMP. A single-bit error flips one bit; a burst flips a run (the slide’s picture is an 8-bit burst).

Human options: ignore, ask again, or repair. Networks do the last two as ARQ (detect, then retransmit) or FEC (enough redundancy to correct).

Block code: k-bit dataword, r redundancy bits, codeword n = k + r. There are 2k datawords and up to 2n possible codewords; only some codewords are valid. Receiver recomputes a syndrome. Syndrome 0 → assume OK. For Hamming, the syndrome is the index of the bad bit.

Parity

Even parity: add a bit so the number of 1s is even. Odd: make it odd. Generator and checker are the same XOR. Example “world” in 7-bit ASCII plus even parity is sent as 8-bit units; a flipped bit makes the syndrome 1.

Simple parity catches every single-bit error and a burst only when the number of bad bits in the unit is odd. Two flips in one unit are invisible.

2D parity: parity on each row and each column. One bad bit fails one row and one column, so you can correct it. Send row by row, parity bits included.

Checksum (one’s complement)

Split the message into m-bit units, add with end-around carry, send the complement. Receiver adds message + checksum; complement of that sum is 0 if clean. IPv4 header checksum covers the header only. TCP/UDP checksum covers header + data. Links prefer CRC for bursts.

10101001 + 00111001 = 11100010. Checksum = 00011101.
Sent: 10101001 00111001 00011101. Sum of the three = 11111111 → complement 00000000 (OK).
A 5-bit burst that flips 4 bits leaves a nonzero syndrome → discard.

CRC

Treat the data as a polynomial. Agree a divisor. Append r = (degree) zeros, divide modulo-2 (XOR, no borrow). The remainder is the CRC, one bit shorter than the divisor. Codeword = data + remainder, exactly divisible by the divisor. Checker divides; nonzero remainder means error.

Slide CRC(7,4), divisor 1011, remainder 110. Codeword ends with those 3 bits. Modulo-2: subtraction is XOR.

Hamming (even parity)

Parity bits sit at powers of 2: r1, r2, r4, r8, … Each checks positions whose index has that bit set. Data 1001101 placed as d7…d1 around the parity bits → codeword 10011100101.

Positions 11→1: d7 d6 d5 r8 d4 d3 d2 r4 d1 r2 r1
= 1 0 0 1 1 1 0 0 1 0 1
Received 10010100101. Checks: r1=1, r2=1, r4=1, r8=0. Syndrome r8 r4 r2 r1 = 01112 = 7. Flip bit 7.

Interleaving: shuffle bits of several codewords. A burst then hits one bit of many words, and Hamming can fix each.

EXTRA Parity misses an even number of flips. Checksums miss many burst patterns. CRC (FCS) is what Ethernet, Wi-Fi, HDLC, and PPP actually use on the link. Correction (Hamming, interleaving) is for links where a retransmission is expensive or impossible.

Flow control

The sender must not outrun the receiver. Both sides buffer. If the receiver buffer fills, frames are lost even when the wire was fine.

  • Simple protocol: no flow control, no error control, no sequence numbers. Send whenever data is ready.
  • Stop-and-wait ARQ: send one frame, wait for ACK (receiver checks CRC). Sequence numbers 0 and 1 only, so a retransmission is not accepted as new.

Stop-and-wait cases: normal ACK; lost frame → timer, resend same number; lost ACK → sender resends, receiver sees the duplicate number and discards but re-ACKs; delayed ACK → the 0/1 number tells a late ACK from the ACK of the next frame.

Pipelining

Several frames in flight. Utilization rises on long or fast links. Two ARQs: Go-Back-N and Selective Repeat.

Performance (slides)

  • Distance 1000 m, speed 500 m/s. Ignore transmission time. RTT = 2×1000/500 = 4 s.
  • Frame 100 bit, total 1000 bit → 10 frames. Stop-and-wait: 10 × 4 = 40 s.
  • Same link, 2 frames in flight: 5 rounds × 4 = 20 s.
Bandwidth–delay product = R × RTT = bits you could have sent while waiting for an ACK.
1 Mbps × 20 ms = 20,000 bits. Frame = 1000 bits → stop-and-wait utilization = 1000/20000 = 5%.
GBN with 15 frames in the window: 15,000/20,000 = 75% (less if frames are resent).

HDLC

Bit-oriented standard for point-to-point and multipoint serial links. Flag framing, bit stuffing, FCS (CRC, 2 or 4 bytes), and a control field for flow and errors.

Connectionless link service: each frame stands alone. Connection-oriented: set up a mode, transfer, then release.

Cousin frames

  • PPP: flag 0x7E, address 0xFF, control 0x03, protocol field, data, FCS. Byte stuffing. LCP configures the link; NCP configures the network protocol (often IP).
  • Cisco HDLC: like HDLC plus a proprietary type field so several network protocols can share the serial link.
  • LAPB is the HDLC-derived reliable link under X.25. Frame Relay and ATM are related WAN framings; ATM uses fixed cells instead of flags.
EXTRA Normal response mode: only the primary may start a transfer; secondaries speak when polled. Asynchronous balanced mode: either side may send (typical of two routers). “Extended” (SNRME, SABME) means a longer sequence field (7-bit → more window). Ethernet does not use HDLC windows; it is connectionless and leaves reliability to TCP.

Who may transmit

FamilyRuleExamples
ContentionCompete. Simple; collapses when busyALOHA, CSMA/CD, CSMA/CA
ControlledTake turnsReservation, polling, token
ChannelizationSplit the mediumFDMA, TDMA, CDMA

A collision is two or more signals on one shared medium at once (bus or hub). Levels become undefined. Switched full duplex has no collision.

ALOHA

Send whenever you have a frame (original wireless, 9600 bps). No carrier sense. Collision → wait a random backoff, retry. Pure: any time, vulnerable time 2T, max throughput ~18%. Slotted: only at slot start, needs sync, vulnerable time T, max ~37%.

CSMA

Listen first. Idle → may send. Collisions still happen: two stations both hear idle, then their signals meet after propagation delay.

  • Non-persistent: if busy, wait a random time, then sense again. Fewer collisions, more idle gaps.
  • 1-persistent: if busy, keep listening; send the instant it is idle. Greedy; stations collide when a long frame ends. Classic Ethernet.
  • p-persistent: if idle, send with probability p, else wait one slot. p = 0.2 means a 20% chance to send this slot.

CSMA/CD (wired shared Ethernet)

Sense, send, and keep listening. Collision → stop, send a jam, retry. After the n-th collision, k = min(n, 10), pick r from 0 … 2k−1, wait r × slot. Slot ≥ 2 Tprop,max. Classic 10 Mbps slot = 512 bit-times = 51.2 µs. Abort after too many collisions (16).

CSMA/CA (802.11)

A wireless sender cannot hear a collision while it transmits, and a hidden terminal may not hear the other sender. So avoid, don’t detect.

  • Wait DIFS (or a shorter SIFS for ACK, CTS, and other high-priority frames). Then a random backoff counted in idle slots.
  • CW backoff picks how many slots to wait (CW = 15, draw 7 → wait 7). Different from p-persistent, which flips a coin each slot.
  • Receiver ACKs after SIFS. No ACK → assume loss, grow CW, retry.
  • NAV: frames carry Duration. Other stations defer even if they cannot hear the data (virtual carrier sense).
  • Optional RTS/CTS (DCF): reserve the medium so hidden terminals hear the CTS and set NAV.
  • EDCA: voice/video get shorter waits than best-effort.

Wi-Fi 4 (802.11n): MIMO, bonding. Wi-Fi 5 (ac): DL MU-MIMO, wider channels. Wi-Fi 6 (ax): OFDMA + UL/DL MU-MIMO. Wi-Fi is the trademark; IEEE 802.11 is the standard.

Controlled & channelization

  • Reservation: a reservation minislot per station, then data for whoever reserved.
  • Polling: primary (master) and secondaries. Select: primary warns, waits ready, then sends. Poll: primary asks each secondary; NAK means nothing to send.
  • Token: stations in a logical ring. Only the token holder sends, then passes the token. Physical cabling need not be a ring.

FDMA: each station a frequency band (FDM below). Cellular, satellite. TDMA: whole band, turns in time (TDM below). CDMA: all stations, all the time, whole band, separated by code.

CDMA Walsh codes are orthogonal. Rules: data 0 → send −1 times the code, data 1 → send +1 times the code, idle → 0. The channel sum is one vector. Station i recovers its bit by the inner product with its code: result / N is +1, −1, or 0. Inner product of a code with itself is N; with another code (or its complement) is 0.

Ethernet frame

Xerox PARC 1973–74, inspired by ALOHA (Metcalfe). IEEE 802.3 in 1983. It won the LAN market. Connectionless: no setup, each frame independent. Unreliable: no link ACK, no LLC flow control — like IP and UDP. TCP repairs it.

Preamble 7BSFD 10101011DA 6BSA 6BType/Len 2BData 46–1500FCS 4B
  • Preamble (alternating 01) and SFD are added by the PHY for clock sync. Not part of the 64-byte count. Wireshark hides them and the FCS.
  • Min frame 64 B = 512 bits so the sender is still transmitting when a collision echo returns. Header+trailer = 18 B → min payload 46 B (pad if shorter).
  • Max frame 1518 B (no preamble), max payload 1500 B: old memory was small, and one station must not own a shared cable.
  • Type/length: value ≥ 1536 (0x0600) is a type (IPv4 = 0x0800). Smaller is a length.
EXTRA With an 802.1Q tag the frame grows by 4 bytes (max 1522). The 64-byte minimum is a CSMA/CD rule. A full-duplex switch port does not need it for collision detection, but NICs still enforce it.

MAC addresses

48 bits on the NIC, written hex with colons (4A:30:10:21:10:1A). First 24 bits: OUI (IEEE, manufacturer). Last 24: vendor serial. Duplicates can exist (factory error or a VM); then change the NIC or override in software.

  • Sent byte by byte, left to right, but inside each byte the LSB goes first. The unicast/multicast bit therefore arrives first.
  • Unicast: I/G = 0, one NIC. Multicast: I/G = 1 (e.g. IGMP). Broadcast: FF:FF:FF:FF:FF:FF. DHCP and ARP need the broadcast.
  • On a shared cable every NIC hears every frame and keeps only its own, the broadcast, or a joined multicast.

Same subnet: frame MAC = the destination host. Remote network: frame MAC = the gateway (default router). IP addresses in the packet do not change. The router builds a new frame.

Speeds and the switch

  • Standard shared Ethernet: 1-persistent CSMA/CD. Cable limit about 2500 m.
  • Fast (100 Mbps): min frame still 64 B but 10× faster, so shared cable drops to 250 m (practice: 100 m UTP). Switched Fast Ethernet is full duplex, no CSMA/CD. Autonegotiation picks a common speed, usually the slower one.
  • Gigabit 802.3z: same frame format, autonegotiation. For the old half-duplex case, min length becomes 512 B (carrier extension); short frames may be packed (frame bursting). There is no Gbps hub. Switched full duplex has no collision, so extension is unused there.

Forwarding

  • Unknown source → learn MAC + port. Known destination → send that port only. Unknown destination, broadcast, or multicast → flood.
  • A port toward another switch holds many MACs.
  • Store-and-forward: whole frame, check CRC, then forward. Needed if you want QoS from the frame type.
  • Cut-through: forward once the DA is seen. Fast, no QoS, may forward a bad CRC. Fragment-free waits 64 B (the old collision window) then cuts through.
  • Auto-MDIX accepts straight or crossover cable. It is not autonegotiation (speed/duplex).

ARP

On the local LAN, a frame needs a MAC. ARP maps IPv4 → MAC. A broadcasts a request (target MAC field all zeros). The owner unicasts a reply. Both sides cache it (arp -a). ARP does not cross a router; the host ARPs for the gateway when the IP is remote.

Loop: redundant switches with empty tables flood a frame out every port, including back toward each other. Copies multiply (a broadcast storm). Operators still want the extra links for backup.

STP (IEEE 802.1D) keeps the physical links but blocks some ports so the active topology is a tree. Give each link a cost (slide example: hops). Elect a root. Each other switch picks a root port (best path to root). Each segment picks a designated port. Other ports are blocked (they do not forward user frames).

VLAN

Without VLANs, linked switches are one big L2 broadcast domain. A VLAN is a logical group. Each VLAN is its own broadcast domain: smaller floods, separate groups (security, department), and you can move a port without moving the cable.

  • Default VLAN: VLAN 1. Unused access ports land here. Do not use it for users.
  • Data VLAN vs voice VLAN. An access port has one data VLAN and may also have one voice VLAN. A VoIP phone is a small 3-port switch; CDP tells the phone which voice VLAN to tag.
  • Native VLAN (trunks only): that VLAN’s frames go untagged. Every other VLAN on an 802.1Q trunk is tagged.
  • 802.1Q tag is 4 bytes inserted after the source MAC: TPID 0x8100 + TCI (priority, DEI, 12-bit VLAN id). The FCS is recomputed.
  • Access port: one data VLAN, toward an end host, untagged on the wire. Trunk: point-to-point between switches (or switch and router), carries many VLANs.
  • Ranges on Catalyst 2960/3650: normal 1–1005 (stored in vlan.dat, created in global config), extended 1006–4094. More than 4000 VLAN ids exist; the switch still has a smaller active limit.

Before no vlan, move member ports elsewhere or they fall back to VLAN 1. Reset a trunk toward access with switchport mode access. Home/NETGEAR: untagged = end device (access), tagged = trunk.

EXTRA Native-VLAN mismatch: one side tags what the other treats as native, so frames leak into the wrong VLAN or get dropped. Keep the native VLAN the same and unused by users. ARP is not a routing protocol. A switch never rewrites the MAC addresses inside a frame; a router does, because it builds a new frame. VLAN 1 and the reserved 1002–1005 token-ring/FDDI VLANs are not deleted.
